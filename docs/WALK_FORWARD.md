# ウォークフォワード検証

実運用に近い順序で精度を測るため、拡大型のウォークフォワード検証を使用する。各窓は次の3期間を持つ。

1. `train_end`以前：モデル学習
2. `train_end`より後、`calibration_end`以前：確率校正
3. `calibration_end`より後、`evaluation_end`以前：未来評価

次の窓では前の評価期間までを学習へ追加できる。ただし、評価期間同士は重複させない。すべての境界はタイムゾーン付き時刻で指定し、逆転、重複、空の期間は処理前に拒否する。

## 出力

- 窓ごとの学習・校正・評価レース数と選択温度
- 条件付きロジットモデルの1着的中率、Brier score、Log loss
- 同じ評価レースに対する一様確率ベースラインの同一指標
- 全評価窓を結合した両モデルの指標
- 全評価予測の確率帯別校正表とECE
- 競馬場、距離帯、頭数、予測信頼度別のモデルと一様確率の比較

## ローカル実行

時点安全な `training.csv` と、事前に決めた窓定義JSONから実行する。

```bash
PYTHONPATH=src python -m keiba_prediction_lab.cli evaluate-walk-forward \
  local/training.csv local/windows.json \
  --min-evaluation-races 300 \
  --max-evaluation-races 500 \
  --report reports/walk-forward.json

PYTHONPATH=src python -m keiba_prediction_lab.cli \
  audit-walk-forward-report reports/walk-forward.json
```

窓定義は配列とし、各要素にタイムゾーン付きの `train_end`、`calibration_end`、`evaluation_end` だけを含める。未知キー、キー重複、境界逆転、評価期間重複、各期間にレースが存在しない窓は拒否する。

JSON成果物には、学習CSVと窓定義ファイルのSHA-256、入力データ版、窓別・全体スコア、校正表、条件別診断を保存する。既存ファイルは上書きしない。Markdown表示とJSON成果物は同じ実行結果から生成する。専用監査はファイルを一度だけ読み、内部SHA-256、厳密なキーと型、窓の時系列、窓別と全体の件数、校正件数、診断区分の一意性を確認する。

`--min-evaluation-races 300 --max-evaluation-races 500`を指定すると、全評価窓を結合したレース数がこの固定範囲外の場合、レポートを保存せず失敗する。これにより、結果を見た後で評価レースを足したり除いたりした成果物を正式な300〜500レース評価として扱わない。窓定義ファイル自体のSHA-256も成果物へ保存される。

頭数は8頭以下、9〜12頭、13頭以上に分ける。予測信頼度はレース内最大勝率を使い、`0.4未満`、`0.4以上0.7未満`、`0.7以上`に分ける。各区分ではレース数と出走馬数を必ず併記し、少数区分の値を全体傾向として扱わない。

現段階は合成データによる動作契約の検証であり、実競馬での性能を示すものではない。実データ源が承認され、時点安全な300〜500評価レースが揃った時点で上記の固定範囲を指定して実測する。300レース以上でも単一の結果だけで改善を証明したとは扱わず、指標の差と条件別の標本数を併記する。
