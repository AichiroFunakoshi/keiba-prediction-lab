# 1着予測精度を改善するための実行基準

## 結論

現時点では、実競馬に対する精度向上を確認できない。GitHubの`main`には、実レースの学習CSV、発走前に固定した予測バンドル、確定結果、払戻表、ウォークフォワード評価成果物が含まれていない。自動テストは実装契約を合成データで検証するものであり、実競馬の的中率を示さない。

直近結果だけを見てモデル係数や特徴量を変更すると、次週の予測精度を上げる根拠にならず、過適合と検証汚染を起こす。このため、改善は次の順序で行う。

1. 発走前に固定した予測と確定結果を変更せず保存する
2. 1着予測の外れ方を診断する
3. 改善仮説を、直近結果とは別の過去期間で時系列検証する
4. 改善候補を固定した後、今週末を将来の評価期間として扱う

## 今回追加した診断

各レースの監査済み予測バンドルと`bet-types-payouts.json`を使用し、次を出力する。

- 1着的中率
- 実勝馬の上位2頭・上位3頭カバー率
- 実勝馬の平均予測順位
- 予測1位の勝率と2位との差
- 予測1位の勝率が40%以上だった不的中数
- 外れの分類
  - `near_miss_rank_2`: 実勝馬が予測2位
  - `top3_miss`: 実勝馬が予測3位
  - `deep_rank_miss`: 実勝馬が予測4位以下

```bash
PYTHONPATH=src python3 -m keiba_prediction_lab.cli \
  diagnose-winner-misses outputs/race-1 outputs/race-2 \
  --format markdown
```

この診断は発走前予測を変更せず、係数も自動更新しない。

## 診断から改善仮説への対応

| 観測された外れ方 | 優先して検証する仮説 | 直ちに行わないこと |
|---|---|---|
| 2位の実勝馬が多く、1位との差が小さい | 1位・2位の識別に効く発走前特徴量、正則化、同条件実績 | 2頭を恣意的に入れ替える |
| 上位3頭に実勝馬が入らない | データ欠損、馬ID結合、近走・距離・馬場・クラス情報の不足 | 三連単の買い目数だけ増やす |
| 高信頼の外れが多い | 確率校正、分布変化、未知条件への過信 | 確率表示だけ手作業で下げる |
| 低信頼レースだけ悪い | 予測対象条件の限定、信頼度別の研究表示 | 低信頼レースを結果後に評価対象から外す |

## 今週末へ向けた採用条件

今週末のレースを予測する前に、次を満たす。

- 今回分の全レースについて、発走前予測バンドルと確定払戻表が対応している
- `diagnose-winner-misses`の分母が欠けていない
- 学習に使う結果は、予測固定時刻より前に確定したレースだけである
- 改善候補は、今週末を含まない固定ウォークフォワード期間で現行モデルと比較する
- 1着的中率だけでなくBrier score、Log loss、ECEも確認する
- 300レース未満の差は改善の証明ではなく、暫定仮説と表示する
- 今週末の予測後はモデルを固定し、結果を見て差し替えない

## 現在の阻害要因

今回分の実ファイルがローカルに存在しないため、現段階では診断値を計算できない。必要なのは、各レースについて次の2点である。

1. 正式パイプラインが発走前に保存した予測ディレクトリ
2. 同じ馬IDで記録した完全な`bet-types-payouts.json`

これらが揃った時点で、本書の診断を実行し、改善仮説を限定する。結果だけから過去の予測を再構成したものは、発走前予測の代用にしない。
