# 馬券種別・固定100円評価

単勝、複勝、馬連、馬単、3連複、3連単を別々に集計する。異なる馬券種の的中率や回収率を合算せず、各買い目は1点100円に固定する。

## 出力指標

馬券種ごとに次を出力する。

- 買い目数と的中数
- 的中率
- 購入額と払戻額
- 回収率
- 最高払戻を除外した回収率
- 最高払戻が全払戻に占める割合
- 上位3件・5件の払戻集中度

最高払戻を除外する場合も、その買い目へ支払った100円は購入額から除外しない。これは、少数の高配当だけで回収率が支えられていないかを見る感度分析である。

## 買い目の同一性

馬連と3連複は順序を持たないため、馬の並びだけを変えた買い目は重複として拒否する。馬単と3連単は着順が異なれば別の買い目として扱う。同一レース・同一馬券種・同一買い目の重複記録は集計しない。

## 事前固定候補の決済

`settle_frozen_bet_type_candidates` は、改変検知済みの発走前スナップショットと、結果確定後に明示的に入力した100円あたりの払戻表を照合する。着順から払戻額を推測せず、単勝、複勝、馬連、馬単、3連複、3連単の全券種について、実際に公表された的中組合せと払戻額を渡す。

- 払戻表は6券種すべてを含める
- 複勝はスナップショットに記録した払戻対象席数以上を含める
- 同着による複数の的中組合せを許容する
- 馬連と3連複は発走前確率表と同じ正規順で入力する
- 確率表に存在しない馬・組合せ、重複、0円以下の的中払戻を拒否する

`evaluate_frozen_bet_type_candidates` はレースIDが一対一に対応する複数のスナップショットと払戻表を決済し、券種ごとの固定100円評価へ渡す。ここでの100円は全券種を同じ条件で比較する反実仮想上の購入額であり、実際の購入記録ではない。

## 払戻表の保存と一括評価

`save_bet_type_race_payouts` は、1レース分の払戻表を `bet-types-payouts.json` として新規保存する。既存ファイルは上書きせず、スキーマ版 `1.0` と正規化した内容のSHA-256を同梱する。`load_bet_type_race_payouts` は決済前にスキーマ版とハッシュを検証する。

評価対象の各ディレクトリには、発走前に固定した `bet-types-shadow.json` と、結果確定後に作成した `bet-types-payouts.json` を置く。複数レースは次のコマンドでまとめて評価できる。

```bash
PYTHONPATH=src python -m keiba_prediction_lab.cli evaluate-bet-types \
  outputs/2026-08-22-race-1 \
  outputs/2026-08-22-race-2 \
  --report reports/bet-types-evaluation.json
```

CLIは両ファイルの改変検知とレースIDの一対一対応を確認し、券種別のMarkdown表を標準出力へ出す。`--report` を指定すると、レースID順に正規化した入力ファイルのSHA-256、発走予定時刻から得た開催日、構造化集計、全レース×6券種の決済台帳を、スキーマ版 `1.2` の `bet-types-evaluation.json` へ保存する。既存レポートは上書きしない。時刻や入力ディレクトリの絶対パスは保存しないため、同じ入力内容からは同じレポート内容を再生成できる。

`load_bet_type_evaluation_artifact` はレポート自体のSHA-256、入力順、レースIDの重複、全券種が全レースを1点ずつ含むこと、決済台帳から再計算した集計が保存集計と一致することを検証する。旧スキーマ `1.0` と `1.1` は読込可能だが、それぞれ決済台帳または開催日を持たないため新規保存はできない。レースの指定順は集計結果と保存内容に影響しない。

## 基準モデルとの対応比較

基準モデルと候補モデルの評価レポートは、次のコマンドで比較できる。

```bash
PYTHONPATH=src python -m keiba_prediction_lab.cli compare-bet-type-reports \
  reports/baseline.json \
  reports/candidate.json
```

`compare_bet_type_evaluation_artifacts` は、両レポートのレースID集合が同一で、各レースの払戻ファイルSHA-256も同一である場合だけ比較する。予測ファイルSHA-256はモデルごとに異なってよい。これにより、異なるレース期間や異なる払戻結果を使った見かけ上の改善を拒否する。

出力は全6馬券種について、候補−基準の的中率差、回収率差、最高払戻除外後の回収率差、最高1件への払戻依存度差をパーセントポイントで示す。馬券種をまたいだ合算値は作らない。

## レース・開催日対応ブートストラップ

決済台帳を持つ2つのレポートは、同一レースを対に保ったまま再標本化できる。

```bash
PYTHONPATH=src python -m keiba_prediction_lab.cli bootstrap-bet-type-reports \
  reports/baseline.json \
  reports/candidate.json \
  --samples 10000 \
  --seed 0
```

各反復ではレースIDを復元抽出し、抽出した同じレース列を基準・候補の両方へ適用する。全券種にも同じ抽出列を使う。既定は1万回、固定シード0、95%パーセンタイル区間であり、同じ入力と設定から同じ結果を再生成できる。

スキーマ `1.2` の開催日を持つレポートでは、同日内の相関を保つクラスターブートストラップも選択できる。

```bash
PYTHONPATH=src python -m keiba_prediction_lab.cli bootstrap-bet-type-reports \
  reports/baseline.json \
  reports/candidate.json \
  --samples 10000 \
  --seed 0 \
  --resampling-unit race-date
```

`race-date` では開催日を復元抽出し、選ばれた日の全レースを一塊として基準・候補・全6券種へ適用する。開催日が2日未満の入力は区間推定に使えない。旧 `1.1` レポートは開催日を持たないため、従来の `race` 単位だけを利用できる。

券種ごとに的中率差、回収率差、最高払戻除外後回収率差、最高1件依存度差の点推定と区間を示す。改善確率は、反復内の候補−基準が正なら1、同値なら0.5として集計する参考値であり、p値や有意差判定ではない。既定のレース単位では開催日内相関を補正しない。開催日単位ではその相関を保つが、どちらも6券種を同時に見る多重比較は補正しない。

ロードマップの最低目安である300レース未満は、結果冒頭に「標本不足・探索的」と明示する。区間が正側だけにあっても、データ品質、期間外検証、モデル選択の影響を別途確認せず改善を断定しない。

## レース別・開催日別の寄与診断

比較全体の差がどの観測結果から生じたかは、次のコマンドで分解できる。

```bash
PYTHONPATH=src python -m keiba_prediction_lab.cli diagnose-bet-type-reports \
  reports/baseline.json \
  reports/candidate.json \
  --top-races 5
```

スキーマ `1.2` の同一レース・同一払戻レポートを使い、全6券種を混ぜずに次を出力する。

- 各レースの両方外れ、基準のみ的中、候補のみ的中、両方的中
- 各レースの候補−基準の払戻差
- 各レースの基準・候補それぞれの買い目
- 開催日ごとの基準・候補の的中数、純的中差、払戻差
- 各券種・各方向で払戻差が大きいレース

`--format json` を指定すると全レース行と開催日集計を機械可読形式で出力する。`--top-races` はMarkdown表示だけを制限し、JSONや内部集計から行を削除しない。

この診断は、高配当依存や特定開催日への偏りなど、次に確認すべき場所を示す。払戻差の原因を説明するものでも、統計的有意差やモデル採用可否を判定するものでもない。

この評価層は購入戦略を変更しない。実購入候補は引き続き、事前固定した三連単1点100円だけであり、他の馬券種は独立した研究評価として扱う。発走前の候補生成と固定方法は [BET_TYPE_SHADOW_FORECASTS.md](BET_TYPE_SHADOW_FORECASTS.md) に定める。
